# Testing & validation

How Xcrack is tested, what it is cross-validated against, and what CI enforces.
The guiding rules come from the project's ASRs and ADRs:

- **Every cryptographic scheme is cross-validated against an independent
  oracle** — published test vectors or a real third-party tool/library — before
  it ships (policy stated in [`../gold/README.md`](../gold/README.md)).
- **Every hostile-input parser is fuzzed**, and the whole recursive engine is
  fuzzed end-to-end.
- **Work is bounded** (depth / bytes / nodes / ratio / time) so a malicious file
  degrades to a per-node error, never a hang or crash
  ([ADR 0004](adr/0004-hostile-input-safety-budgets.md)).
- **The default build is pure-Go and cgo-free**; the GPU path is an opt-in
  exception validated separately and never built by CI
  ([ADR 0001](adr/0001-pure-go-no-external-binaries.md)).

A GPU/accelerator result is never trusted on its own: the format's CPU verifier
re-checks every candidate the device flags, so a faulty backend can only waste
time, never cause a false positive.

## Categories of tests

### 1. Known-answer and unit tests

Each primitive and scheme has unit tests that pin its output to known-answer
vectors — e.g. the phc-winner-argon2 reference vectors for Argon2
(`xcrypto/prim/argon2/argon2_test.go`), and the PDF handler against libqpdf
known answers (`xcrypto/scheme/pdf/pdf_kat_test.go`).

### 2. Cross-validation against external oracles

The core discipline: a scheme must reproduce, byte-for-byte, the output of an
independent implementation. Fixtures produced by third-party tools are
**committed in-tree** (indexed in [`../gold/README.md`](../gold/README.md), with
per-directory `ATTRIBUTION.md` provenance) so the cross-validation stays
reproducible even if the upstream source moves or disappears.

| Oracle (tool / library) | Validates | Fixture location |
| --- | --- | --- |
| **qpdf** | PDF RC4-40/128, AES-128, AES-256 (R6), 16-salt corpus | `xfileformats/formats/pdf/testdata/qpdf/` |
| **msoffcrypto-tool** | legacy MS Office RC4 / XOR (+ byte-exact decrypted gold) | `xfileformats/formats/msoffice/testdata/` |
| **pykeepass** + **KeePassXC** (two oracles) | KeePass KDBX3/KDBX4 | `xcrypto/scheme/keepass/testdata/*.kdbx` |
| **LibreOffice** | ODF AES-256-CBC | `xfileformats/formats/odf/testdata/` |
| **Apple** Pages/Numbers/Keynote 14.5 | iWork verifier | `xcrypto/scheme/iwork/testdata/*.iwpv2` |
| **age** CLI | age scrypt passphrase | `xcrypto/scheme/age/testdata/hello.age` |
| **GnuPG** CLI | symmetric OpenPGP (`gpg -c`) | `xcrypto/scheme/pgp/testdata/hello.gpg` |
| **7-Zip** `-mhe=on` / **rar** `-hp` | header-encrypted archives | `xfileformats/formats/archive/testdata/hdr.{7z,rar}` |
| genuine **macOS** | encrypted DMG | `xfileformats/formats/dmg/testdata/*.dmg` |
| **John the Ripper** `dmg_common_plug.c` | DMG vectors (13) | `xcrypto/scheme/dmg/testdata/john_vectors.txt` |
| **jackcess** `PasswordUtil` | MS Access Jet header decode | `xfileformats/formats/access/jet_test.go` |

| geth / MyEtherWallet + **pycryptodome** | Ethereum keystore | `xcrypto/scheme/ethkeystore/ethkeystore_test.go` |
| **hashcat** canonical example hashes | `hashline` emitters (`-m 9400/9500/9600/10500/10700/13600`) | `xcrypto/hashline/hashline_test.go` |
| independent MS-OVBA reference (+ Didier Stevens) | VBA project salted-SHA-1 | `xcrypto/scheme/vbaproject/`, generated by [`../gold/vba/vba_oracle.py`](../gold/vba/vba_oracle.py) |

**Live oracle cross-checks** (not committed; skip cleanly when the tool/env is
absent) complement the committed corpora:

- `XCRACK_QPDF_LIVE=1` → `TestQPDFCrossValidation` runs real `qpdf` with random
  salts (`xfileformats/formats/pdf/qpdf_test.go`). Its deterministic counterpart
  `TestQPDFVectors` replays the committed 16-salt corpus with no env var.
- `XCRACK_BKCRACK=/path/to/bkcrack` → `TestExternalBkcrackReal` and
  `TestExternalBkcrackRecoverPasswordReal` validate the ZipCrypto
  known-plaintext offload both directions
  (`xcrypto/scheme/zipcrypto/offload_test.go`).
- `scripts/hashcat-xval.sh` has real **hashcat** crack `xcrack hashline` output
  back to the known password (`-m 9600/10500/10700/13600`), using qpdf to build
  the PDF inputs. Needs an OpenCL backend; not part of CI.

### 3. Fuzzing

Thirty-two `Fuzz*` targets cover every parser that touches untrusted bytes plus
the whole engine:

- **Format parsers** — PDF (`FuzzProbe`, `FuzzRebuild`), CFB/OLE2 (`FuzzOpen`),
  ZIP / 7z-RAR / Office / ODF (`FuzzEntries`), age / DMG / iWork / KeePass /
  OOXML / PGP (`FuzzProbe`), Access Jet, SSH/PEM keys, PuTTY, JKS, PKCS#12,
  SQLCipher, Ethereum wallet, VBA project.
- **Candidate engine** — the mask/rule compiler (`FuzzCompileMask`,
  `FuzzCompileRules`, `FuzzParseText`), context/PCFG generators.
- **The whole recursive engine** — `FuzzProcess`
  (`xcrack/pkg/xcrack/fuzz_test.go`) drives arbitrary bytes through probe →
  decompose → verify and asserts "no panic".

Committed **seed corpora and regression crashers** live under each package's
`testdata/fuzz/`. CI replays them deterministically on every run (below); a
nightly job does timed exploratory fuzzing.

### 4. Golden fixtures

[`../gold/README.md`](../gold/README.md) is the single provenance index: tables
of fixture path → source → expected answer, plus the cross-validation policy.
Fixtures live in ~26 per-format `testdata/` directories with ~13 authoritative
`ATTRIBUTION.md` files. The deterministic qpdf 16-salt set, for example, is what
caught an Algorithm-2.B off-by-one in the PDF R6 handler.

### 5. Hostile-input / resource-budget tests

[ADR 0004](adr/0004-hostile-input-safety-budgets.md)'s budgets are exercised
directly in `xcrack/pkg/xcrack/bomb_test.go`:

- `TestZipBomb` — a 200 MiB entry bounded at `MaxEntrySize`.
- `TestFanOutBomb` — entry fan-out bounded at `MaxNodes`.
- `TestTotalBytesBudget` — the `MaxTotalBytes` cap.
- `TestCycleDetection` — a content-hash quine loop → `StatusLimitExceeded`.
- `timelimit_test.go` — the time `Budget`.

A `recover()` guard wraps every format call (in `xfileformats/registry.go` and
the engine's `decompose.go`), so a parser panic on hostile input becomes a
per-node error; the fuzz targets are the panic exercisers.

### 6. GPU / OpenCL tests (`-tags opencl`)

All gated behind `//go:build opencl` and **never built by the default `go build`
or CI**. The default build has a counterpart (`//go:build !opencl`)
`TestDefaultBuildHasNoGPU` asserting `Built()==false` and that the entry points
return `ErrNotBuilt`.

- **Kernel self-test / cross-validation** (`xcrack/pkg/accel/accel_opencl_test.go`):
  `TestGPUSelfTest`, `TestGPUBatchMatchesReference`, `TestGPUBatchSHA256And512`,
  `TestGPUOldOfficeKeySearch`, `TestGPUPDFKeySearch`, `TestGPUSaltedSHA1`,
  `TestAutotuneBatch` — each kernel's output is compared byte-for-byte to the
  pure-Go reference.
- **Live engine offload** (`xcrack/pkg/xcrack/accel_opencl_engine_test.go`):
  `TestOpenCL{WinZipAES,DMG,ODF,RAR5,VBA,OfficeAgile}Live` crack real fixtures
  through the full engine with a device wired in.
- **CLI GPU wiring** (`xcrack/cmd/xcrack/*_opencl_test.go`):
  `TestSweepKeyspaceGPU`, `TestSweepPDFKeyspaceGPU` — the `--gpu` key-search
  path, including the authoritative CPU re-check of any hit.

These run on **pocl** (CPU OpenCL) in environments with no GPU, so the kernels
are proven correct even without hardware.

## What CI enforces

Two workflows (`.github/workflows/`):

**`ci.yml`** (push to `main`/`rom`/`claude/**`, every PR, manual) — two jobs:

- **test** — installs reference tools (`qpdf`, `p7zip-full`, best-effort
  `rar`/`unrar`), then:
  - `go build ./xcrypto/... ./xfileformats/... ./xcrack/...`
  - `go vet ./xcrypto/... ./xfileformats/... ./xcrack/...`
  - a `gofmt -l` check that fails on any unformatted file
  - `go test -race ./xcrypto/... ./xfileformats/... ./xcrack/...` (also replays
    the committed fuzz seed corpora, including regression crashers)
  - `govulncheck ./...` per module (non-blocking)
- **fuzz** — `go test -run='^Fuzz' ./...` replays every `Fuzz*` target over its
  seed corpus with no random exploration, so it covers all 32 targets and cannot
  flake.

**`fuzz-nightly.yml`** (cron, non-blocking) — timed exploratory fuzzing
(`scripts/fuzz.sh 60s`) and the live `XCRACK_QPDF_LIVE=1` qpdf cross-validation;
uploads any crashers as an artifact.

CI runs entirely on the **pure-Go default build**; it never passes `-tags
opencl`.

## Running the tests

From the repo root (see the [`Makefile`](../Makefile)):

```sh
make check      # what CI runs: gofmt check + go vet + -race test suite
make test       # the full suite (no race detector)
make race       # the suite under -race
make fuzz           # exploratory fuzzing, 20s/target (make fuzz DUR=60s to extend)
go test ./xcrypto/... ./xfileformats/... ./xcrack/...   # one module or all

# GPU path (needs an OpenCL SDK + runtime; pocl works on CPU):
go test -tags opencl ./xcrack/pkg/accel/ ./xcrack/pkg/xcrack/ ./xcrack/cmd/xcrack/
```

See [`PERFORMANCE.md`](PERFORMANCE.md) for the measured per-format verify rates,
and [`CRACKING.md`](CRACKING.md) for how each scheme is attacked and what the GPU
tier accelerates.
